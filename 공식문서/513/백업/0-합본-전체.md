# 원문 — Backing up and restoring IBM Software Hub (5.1.x 허브) `[2026-09-01 수집]`

경로: IBM Software Hub **5.1.x** → Administering → Backing up and restoring IBM Software Hub
문서 갱신일: 2026-06-26 (© 2024 표기) / "older version" 배너 = 5.1.x 판 맞음

> ★우리 판정 (모비스 = NFS·폐쇄망·PROD):
> ① 지원표 NFS 행 = **오프라인 same/different cluster (Kopia 또는 Restic) ✓ 만** — 온라인 열에 NFS 없음 → **NFS 는 온라인 백업 불가 [확정]**. 런북의 오프라인 선택은 유일한 길.
> ② 폐기 예고에서도 **NFS 의 Kopia/Restic 오프라인은 계속 지원** — 경로 안전 [문서].
> ③ IBM 권고는 온라인(다운타임↓)이나 NFS 라 불가 → **다운타임 필연** — C5(다운타임 창 협의)의 문서 근거.
> ④ OADP utility(배포 전체) vs volume backup utility(PVC 파일만) — **택일 아님**, 우리 정본은 OADP. volume utility 는 런북 p.46~47 의 cpdbr-pvc·runtime-mode 부품(용량 추정 du-pv 조연)으로만 등장.

## 원문 요지 (전문 번역)

IBM Software Hub 는 온라인·오프라인 백업/복원을 지원한다.

**Online backups**: 백업 중 정상 운영 계속. CSI 볼륨 스냅샷으로 최소 중단.

**Offline backups**: 서비스를 정지(quiesce)시켜 일관된 상태로 만든 뒤 백업. 백업 참여 서비스의 외부 작업은 quiesce~backup~unquiesce 전 구간 중단. 방법: ①S3 호환 오브젝트 스토어에 Kopia/Restic 백업 ②Portworx 볼륨 스냅샷 ③별도 PVC 또는 S3 에 볼륨 데이터 백업.

대용량 데이터는 오프라인 다운타임이 크므로 **온라인 권장** (← 모비스는 NFS 라 불가).

**Deprecation notices**: 오프라인 백업/복원은 향후 릴리스에서 지원 축소 예정. 예외(계속 지원):
- **NFS — same/different cluster, Kopia 또는 Restic ✓** ★모비스 해당
- Amazon EBS / EFS — same cluster, Kopia only
- (참고) NetApp Astra Control Center 온라인은 5.1.2 에서 폐기 → Trident protect 로 대체

**Supported backup and restore scenarios**:
- 온라인: 같은 클러스터(인스턴스 프로젝트, CSI 스냅샷) / 다른 클러스터(배포 전체, CSI 스냅샷)
- 오프라인: 같은 클러스터(CSI 또는 Restic) / 다른 클러스터(배포 전체, Restic) / 볼륨 데이터만(볼륨 스냅샷·백업)

**Supported storage types (표 발췌 — 모비스 관련)**:
```
NFS                     오프라인 same ✓ (Kopia/Restic) · 오프라인 different ✓ (Kopia/Restic) · 온라인 × · DR ×
ODF (참고: 삼성)         오프라인 same ✓ · different ✓ · 온라인 same ✓(OADP/Fusion) · 온라인 different ✓(Fusion만) · DR ×
Portworx / NetApp / EFS / Nutanix — 모비스 무관 (생략, 원문 표 참조)
```

**Backing up and restoring service data**: 특정 서비스만은 export/import (Migrating data between installations) 로도 가능.

하위 문서: Services that support backup and restore / Installing backup and restore software (OADP·Fusion·Trident·Portworx·volume utility) / Online backup and restore / **Offline backup and restore (OADP utility)** ★수집 대상 / Offline backup and restore (volume backup utility) / Uninstalling

## 부록 — Installing backup and restore software (허브, 2026-06-26) `[9/1 수집]`

You can back up and restore IBM Software Hub deployments with the following software:
IBM Software Hub OADP utility / IBM Fusion / NetApp Astra Control Center / Portworx

하위: OADP utility 설치·구성 ★ / Fusion 용 / NetApp Trident protect 용 / Portworx 비동기 DR 용 /
**volume backup and restore utility — "cpd-cli 설치 시 함께 설치됨"** (별도 설치 없음)

> 판정: 모비스(NFS)는 자격 되는 게 **OADP 하나뿐** — Fusion/Trident/Portworx 는 전용 스토리지 전제 [확정].
> volume utility(du-pv 줄자)는 cpd-cli 에 내장 — 반출물 추가 없음, cpdbr-agent 컴포넌트만 옵션.

### 3.2 환경변수

### 3.3 OCP 클러스터에 컴포넌트 설치 (★표준 순서)

```bash
${OC_LOGIN}
# ① OADP_PROJECT 프로젝트 생성
# ② Restic 전 노드 스케줄 허용
oc annotate namespace ${OADP_PROJECT} openshift.io/node-selector=""
# ③ ★cpdbr-tenant 설치 (런북에 없는 단계 — C6)
#    사설 레지스트리 클러스터:
cpd-cli oadp install \
--component=cpdbr-tenant \
--namespace ${OADP_PROJECT} \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--cpdbr-hooks-image-prefix=${PRIVATE_REGISTRY}/cpdbr-oadp:${VERSION} \
--cpfs-image-prefix=${PRIVATE_REGISTRY} \
--skip-recipes \
--log-level=debug \
--verbose
#    (Entitled Registry 클러스터는 prefix 옵션 없이 동일)
# ④ Red Hat OADP 오퍼레이터 설치 (폐쇄망: OLM restricted network 문서)
# ⑤ S3 자격증명 시크릿 — 이름 반드시 cloud-credentials, 특수문자(#) 금지
cat << EOF > credentials-velero
[default]
aws_access_key_id=${ACCESS_KEY_ID}
aws_secret_access_key=${SECRET_ACCESS_KEY}
EOF
oc create secret generic cloud-credentials \
--namespace ${OADP_PROJECT} \
--from-file cloud=./credentials-velero
# ⑥ DPA 생성 (아래 권장 구성 — cpd-cli oadp dpa create 로도 가능하나 수동 권장)
```

권장 DPA (요지 — 런북 p.44 와 거의 동일, 차이 ★2건):
- customPlugins: cpdbr-velero-plugin 하나 / defaultPlugins: aws·openshift·csi — ★**"Restic 만 쓰면 csi 제거"** (Important)
- velero podConfig: limits cpu ${VELERO_POD_CPU_LIMIT}·memory 4Gi, requests 500m·256Mi + ★`resourceTimeout: 60m` (런북에 없음)
- nodeAgent: enable true·uploaderType restic·timeout 72h(부족 시 증가 — pod volume timeout 에러 대응), limits cpu ${NODE_AGENT_POD_CPU_LIMIT}·memory 32Gi(Restic OOMKilled 시 증가), tolerations icp4data
- backupImages: false / backupLocations: aws·s3ForcePathStyle "true"·s3Url·cloud-credentials
- 자체서명 인증서 오브젝트 스토어: objectStorage.caCert 에 base64 인증서 추가
- (5.1.0~5.1.2 + Orchestrate 설치 시 appcon-plugin 추가 — 모비스 5.1.3·Orchestrate 없음 → 해당 없음)

설치 후 확인:
```bash

cpd-cli oadp backup-location list      # PHASE Available
```

## 2. Creating an offline backup

- **2.1 모드**: 기본 Kubernetes 모드. ★스케줄러 백업·모든 복원 = Kubernetes 모드 필수(클러스터 관리자). REST 모드는 긴 백업의 토큰 만료 회피용(백업·체크포인트만) — 모비스 불사용
- **2.2 스케줄러 백업** (설치 시 — 5.1.1+):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp client config set namespace=${OADP_PROJECT}
cpd-cli oadp backup precheck --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --exclude-checks ValidVolumeSnapshotClass --hook-kind=checkpoint --log-level=debug --verbose
cpd-cli oadp backup create ${PROJECT_SCHEDULING_SERVICE}-offline --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --prehooks=false --posthooks=false --with-checkpoint --log-level=debug --verbose --hook-kind=checkpoint --selector 'icpdsupport/ignore-on-nd-backup notin (true)'
cpd-cli oadp backup validate --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --backup-names ${PROJECT_SCHEDULING_SERVICE}-offline --log-level trace --verbose --hook-kind checkpoint
```
  (5.1.0 은 --backup-type singleton 없이. 5.0 백업은 5.1 복원 불가. s390x 는 x86 워크스테이션에서)
- **2.3 테넌트 백업 ★핵심 — 런북에 없던 실제 명령**:
  - Note: ★**NFS 는 no_root_squash 필수** / 백업 중 일부 파드 Running 은 정상(수동 종료 불필요)
  - Important [9/2 대조로 추가]: 5.1.0/5.1.1→5.1.2 업그레이드 이력이 있으면 **새 백업 필수** (모비스 설치 계보 실측 — 5.1.3 직설치면 무관)
  - (5.1.0 EDB 복제 PVC 라벨 복구 — 5.1.3 은 해당 시만)
  - 사설 레지스트리 클러스터:
```bash
cpd-cli oadp tenant-backup create ${TENANT_OFFLINE_BACKUP_NAME} \
--namespace ${OADP_PROJECT} \
--vol-mnt-pod-mem-request=1Gi \
--vol-mnt-pod-mem-limit=4Gi \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--mode offline \
--image-prefix=PRIVATE_REGISTRY_LOCATION/ubi9 \
--log-level=debug \
--verbose &> ${TENANT_OFFLINE_BACKUP_NAME}.log&
```
  - (Entitled Registry 클러스터는 --image-prefix=registry.redhat.io/ubi9)
  - Note: 볼륨 백업 단계 실패 시 --vol-mnt-pod-mem-limit 증가 (TB급 데이터)
  - 확인:
```bash
cpd-cli oadp tenant-backup list                                   # Completed
cpd-cli oadp tenant-backup status ${TENANT_BACKUP_NAME} --details  # cpd-tenant-xxx(리소스)·cpd-tenant-vol-yyy(볼륨)
cpd-cli oadp tenant-backup log ${TENANT_BACKUP_NAME}
```
  - Best practice: 외부 DB 연동 서비스는 외부 DB 도 같은 시점 백업
- **2.4 백업 후 작업**: RStudio(5.1.2+ 유지보수 해제)·Data Refinery(5.1.0 재기동)·wx.ai(5.1.0 스케일업) — 모비스 전부 해당 없음

```

  Note: ★NFS 는 no_root_squash 필수 / 5.1.0→5.1.2 업그레이드했다면 새 백업 필수 / (5.1.0 만) EDB 복제 PVC 라벨 해제 선행

>    원문 Important: "PV 백업만으로는 DR 불충분(시크릿 등 K8s 오브젝트 필요)" — 업그레이드 실패 롤백 도구가 아님.
>    운영자·cpfs 프로젝트는 백업 불가(인스턴스 NS 만). → 우리 보험은 OADP tenant 백업이 정본.
> ② ★런북 수수께끼 해소(정정): 런북 p.46~47 의 cpdbr-pvc(200Gi) 생성 = 이 유틸의 backup-restore init
>    --pvc-name cpdbr-pvc 용 저장 PVC. runtime-mode= 되돌리기도 이 유틸 계열.
>    (앞서 "du-pv 부품"이라 했던 것보다 정확한 정체 — du-pv 는 별도 volume-util 기능)
>    즉 런북은 이 유틸의 준비물만 만들고 실제 volume-backup create 는 안 함 — 잔재/보조 준비로 판정.
> ③ NFS no_root_squash 요건 여기도 명시 (OADP Restic 과 동일) — 실측 1건으로 겸용
> ④ 쓸모 있는 조각: WML 정지 훅(startQuiesce.sh), ws_runtimes 노트북 런타임 정지(oc delete rta ...)
>    — 볼륨 백업 전제작업이지만, 다운타임 창에서 "서비스 정지 수단"으로 참고 가치

## 구성 (4장 요지)

### 1) Backing up IBM Software Hub volumes (허브)
스토리지에 따라 볼륨 스냅샷(Portworx) 또는 볼륨 백업(PVC/S3). 일부 서비스는 별도 백업 체계(지원표 참조).

### 2) Volume backup prerequisite tasks (전제작업)
- 전 서비스 Completed 확인 (get-cr-status)
- CCS ConfigMap(cpd-ccs-maint-aux-qu-cm) — 5.1.0 만
- ★Watson Studio Runtimes: 노트북 런타임·잡 전부 정지 — `oc delete rta -l type=service,job -l app.kubernetes.io/name=ibm-cpd-ws-runtimes`
- SPSS·Data Refinery(5.1.0)·Match360(5.1.1) — 모비스 무관/버전 외
- ★WML 준비: 스케줄 잡 비활성 + 실행 중 잡 정리 —
  `oc -n ${PROJECT_CPD_INST_OPERANDS} get pods -l app=wml-deployment-manager -o name | xargs -I{} oc -n <service_namespace> exec {} -- bash -c "/opt/ibm/wml-online-scoring/runtime-manager/bin/startQuiesce.sh <timeout_in_seconds>"`

### 3) Creating volume snapshots — **Portworx 전용** → 모비스 해당 없음
cpd-cli backup-restore snapshot create/status/list (Stork 2.3.3+ 필요, 인스턴스 NS 만).

### 4) Backing up volumes to a PVC or object store
- 요건: cluster-admin 급 권한 / ★NFS 는 no_root_squash / EBS 미지원 / 인스턴스 NS 만
- 동작: quiesce(서비스 훅으로 쓰기 중단 — 단순 스케일다운보다 최적화) → 볼륨 백업 → unquiesce
- 초기화(★런북 cpdbr-pvc 가 여기 쓰임):
```bash
# S3 저장 (폐쇄망):
cpd-cli backup-restore init --namespace $NAMESPACE --pvc-name cpdbr-pvc --image-prefix=${PRIVATE_REGISTRY_LOCATION} --provider=s3 --s3-endpoint="s3 endpoint" --s3-bucket=cpdbr --s3-prefix=$NAMESPACE/
# 별도 PVC 저장 (폐쇄망):
cpd-cli backup-restore init --namespace $NAMESPACE --log-level=debug --verbose --pvc-name cpdbr-pvc --image-prefix=${PRIVATE_REGISTRY_LOCATION} --provider=local
```
- EDB Postgres 데이터·시크릿 백업 잡(zen-edb-volumes-backup-job — 원문에 전체 yaml, 임베디드 EDB 만) 선행
- 백업 두 방식: 수동(quiesce → dry-run 으로 PVC 물린 잡·파드 점검 → volume-backup create --skip-quiesce=true → unquiesce) / 자동(volume-backup create 한 방)
- 같은 이름 재실행 = 증분, 새 이름 = 전체
- 부속: volume-backup download/status/list(--details 로 크기)/logs, 끝나면 reset --force
- Tip: --cleanup-completed-resources 로 완료·실패 잡 자동 정리

## 5) Restoring volumes (복원 편 — 9/1 추가 수집, 역시 불사용·요지)

- **snapshot-restore** (Portworx 전용 — 해당 없음): quiesce --force → dry-run → snapshot-restore create --skip-quiesce → unquiesce. 서비스별 전처리(RStudio·SPSS·WS)·후처리(Spark·WS 잡 재스케줄·WML) 표 있음
- **volume-restore** (PVC/S3): init(백업 때와 동일) → `volume-backup upload -f cpd-volbackups-<이름>-data.tar` → quiesce → dry-run → `volume-restore create <이름> --from-backup <이름> --skip-quiesce=true` → EDB 복원 잡(zen-edb-volumes-restore-job — 원문에 전체 yaml) → unquiesce. status/list/logs/reset 부속 동일
- **Restoring Watson Studio** (볼륨 복원 전 정리): 설치 잡 삭제(dsx-requisite-pre-install-job·change-pvc-permissions·dsx-userhome-pre-install-job·usermgmt-ldap-sync-cron-job·zen-requisite-job·pv-prep-job) + 활성 환경·잡 아티팩트 삭제(`oc delete rta -l type=job` / `-l type=service`) — 새로 설치한 클러스터로 복원 시엔 불필요
- ★**Restoring Watson Machine Learning — 트러블슈팅 (OADP 복원 후에도 유효한 처방)**:
  wml-deployment-manager 가 복구 안 되면 → init 로그에서 etcd 연결 실패 확인
  (`oc logs -l app=wml-deployment-manager -c init-container` — "wml-cpd-etcd:2379 is unhealthy" 반복)
  → ①wml-cpd-etcd-0·1·2 재시작 ②wml-deployment-manager 재시작 ③agent·envoy init 로그 확인
  (`oc logs wml-deployment-agent-0 -c init-container` / `oc logs -l app=wml-deployment-envoy -c init-container`)
  → 연결 실패면 wml-deployment-agent-0·wml-deployment-envoy 재시작 ④그래도 안 되면 클러스터 재부팅
  → 롤백 런북의 "WML 검증 실패 시" 처방으로 채택 [문서]

## 6) Uninstalling (5.1.x — 요지)
