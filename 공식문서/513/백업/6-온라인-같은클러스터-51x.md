## Before you begin

- 서비스 지원 확인: 표 + `cpd-cli oadp service-registry check --tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} --verbose --log-level debug`
- 미지원 서비스: 서비스 자체 백업 절차(표의 Notes) 또는 export-import 로 대체
- 요건: cpfs 최소 Small / **전 서비스 동일 릴리스** / 컨트롤플레인 단일 NS / 오퍼레이터·인스턴스 정상 상태

## Overview

온라인 백업 = K8s 리소스는 오브젝트 스토리지에, CSI 스냅샷은 **클러스터 로컬에** 저장 → 같은 클러스터로만 복원 가능.
(재해 대비는 different cluster 온라인 문서 참조 권고)
5단계: ①백업 준비 ②온라인 백업 생성 ③복원 전 청소 ④복원 ⑤복원후 작업

## 1. Preparing to back up (요지)

- 1.1 환경변수: OC_LOGIN·CPDM_OC_LOGIN·OPERATORS·OPERANDS·SCHEDULING·TETHERED(_LIST)·PRIVATE_REGISTRY_LOCATION(★ubi-minimal — "백업·복원 명령 실행에 필요")·OADP_PROJECT·TENANT_BACKUP_NAME(+Orchestrate 시 App Connect 2종)
- 1.2 버전 확인: `oc get csv -A | grep "OADP Operator"` → 1.4.x / `cpd-cli oadp version` → 5.1.0
- 1.3 (선택) 용량 추정 — ★Note: **운영 환경에서 쓰지 말 것**. cpdbr-agent 설치(`oadp install --component=cpdbr-agent --namespace=${OADP_PROJECT} --cpd-namespace=${PROJECT_CPD_INST_OPERANDS}`) + `CPDBR_ENABLE_FEATURES=volume-util` + `cpd-cli oadp du-pv`
- 1.4 MongoDB ConfigMap 잔재 제거(4.8.4 이하 업그레이드 이력 시): `oc delete cm zen-cs-aux-br-cm zen-cs-aux-ckpt-cm zen-cs-aux-qu-cm zen-cs2-aux-ckpt-cm`
- 1.5 PostgreSQL(CNPG·EDB) 프라이머리↔복제 동기화 점검 (트러블슈팅 문서)
- 1.6 (5.1.0 만) CCS ConfigMap 갱신 — download-images 파드 Running 시 무시 목록에 추가 (백업 때마다 재확인)
- 1.7 IKC: 대형 enrichment 잡과 백업 동시 실행 회피 / Match360(5.1.1) 라벨 — 모비스 미설치
- 1.8 외부 볼륨 제외: `oc label pvc <이름> icpdsupport/ignore-on-nd-backup=true` (복원 때 수동 재생성 필요할 수 있음)
- 1.9 전 서비스 Completed 확인: `cpd-cli manage get-cr-status --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}`

## 2. Creating an online backup (모비스 사용 불가 — 기록용 요지)

- 2.1 모드: 기본 Kubernetes 모드(클러스터 관리자 로그인 필요). REST 모드는 백업·체크포인트 전용(긴 백업의 토큰 만료 회피용) — ★스케줄러 백업·모든 복원은 Kubernetes 모드 필수. 되돌리기: `cpd-cli oadp client config set runtime-mode=`
- 2.2 스케줄러 백업 (5.1.1+):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp client config set namespace=${OADP_PROJECT}
cpd-cli oadp backup precheck --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --exclude-checks ValidVolumeSnapshotClass --hook-kind=checkpoint --log-level=debug --verbose
cpd-cli oadp backup create ${PROJECT_SCHEDULING_SERVICE}-online --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --prehooks=false --posthooks=false --with-checkpoint --log-level=debug --verbose --hook-kind=checkpoint --selector 'icpdsupport/ignore-on-nd-backup notin (true)'
cpd-cli oadp backup validate --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --backup-names ${PROJECT_SCHEDULING_SERVICE}-online --log-level trace --verbose --hook-kind checkpoint
```
  (5.1.0 은 --backup-type singleton 없이. 5.0 백업은 5.1 에서 복원 불가 — 새로 찍을 것. s390x 는 x86 워크스테이션에서)
- 2.3 테넌트 백업: (5.1.0 EDB 복제 PVC 라벨 복구 명령) →
```bash
cpd-cli oadp tenant-backup create ${TENANT_BACKUP_NAME} --tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} --log-level=debug --verbose
cpd-cli oadp tenant-backup list                                  # Completed
cpd-cli oadp tenant-backup status ${TENANT_BACKUP_NAME} --details   # cpd-tenant-xxx(리소스)·cpd-tenant-vol-yyy(볼륨)
cpd-cli oadp tenant-backup log ${TENANT_BACKUP_NAME}
```
- Best practice: 외부 DB 연동 서비스는 외부 DB 도 같은 시점 백업(복원 시 데이터 정합)

## 3. Cleaning up the cluster before a restore ★오프라인과 공유

인스턴스 리소스는 다른 NS 의 오퍼레이터·컨트롤러가 관리 — finalizer 정리 후 삭제해야 안전.
```bash
${OC_LOGIN}
# 스크립트 출처: github.com/IBM/cpd-cli/tree/master/cpdops/5.1.3  ★배치 A cpdops 경로 근거
./cpd-pre-restore-cleanup.sh --tenant-operator-namespace="${PROJECT_CPD_INST_OPERATORS}"
# 오퍼레이터 NS 가 없거나 특정 NS 지정 삭제:
./cpd-pre-restore-cleanup.sh --additional-namespaces="${PROJECT_CPD_INST_OPERATORS},${PROJECT_CPD_INST_OPERANDS}"
```

## 4. Restoring to the same cluster ★오프라인과 공유 (오프라인판으로 최종 확정 예정)

- 4.1 스케줄러 복원 — ★선행: **언인스톨** (Uninstalling the scheduling service — 삼성 수집분과 동일 원칙):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp restore create ${PROJECT_SCHEDULING_SERVICE}-restore --from-backup=${PROJECT_SCHEDULING_SERVICE}-online --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --include-cluster-resources=true --skip-hooks --log-level=debug --verbose
```
- 4.2 인스턴스 복원 — ⛔다른 NS 로 복원 불가 / Failed·PartiallyFailed → 청소부터 재시작 / 유지보수 모드였던 CR 은 복원 후 수동 해제:
```bash
cpd-cli oadp tenant-restore create ${TENANT_BACKUP_NAME}-restore --from-tenant-backup ${TENANT_BACKUP_NAME} --verbose --log-level=debug &> ${TENANT_BACKUP_NAME}-restore.log&
cpd-cli manage get-cr-status --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}     # 전부 Completed/Succeeded
cpd-cli oadp tenant-restore list
cpd-cli oadp tenant-restore status ${TENANT_BACKUP_NAME}-restore --details      # cpd-tenant-r-xxx 하위들
cpd-cli oadp tenant-restore log ${TENANT_BACKUP_NAME}-restore
```

## 5. Post-restore tasks (모비스 해당분만 — 전체는 원문)

- 5.1 RSI 패치/HTTP 프록시 적용분: `cpd-cli manage apply-rsi-patches --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS} -vvv` (evictor 크론이 30분마다 자동 패치 — 수동 실행은 선택)
- 5.8 ★OpenScale: 진행 중이던 모델 평가 상태 리셋 필요 (별도 문서 "Resetting status of ongoing Watson OpenScale model evaluations")
- (미설치라 무관: Cognos 포트 패치·Data Replication 재시작·IKC 잡/파드 재시작·Assistant 재훈련·DataGate/MANTA/MongoDB)
