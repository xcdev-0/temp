## 2. Creating an offline backup

### 2.1 모드
기본 Kubernetes 모드(클러스터 관리자 로그인). REST 모드는 긴 백업의 토큰 만료 회피용.
Important: 스케줄러 백업과 모든 복원은 Kubernetes 모드.
```bash
cpd-cli oadp client config set runtime-mode=rest-client   # REST 로
cpd-cli oadp client config set runtime-mode=              # Kubernetes 로 되돌림
```

### 2.2 스케줄러 백업 (설치 시) — 5.1.1 and later
```bash
${OC_LOGIN}
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp client config set namespace=${OADP_PROJECT}

cpd-cli oadp backup precheck \
--backup-type singleton \
--include-namespaces=${PROJECT_SCHEDULING_SERVICE} \
--exclude-checks ValidVolumeSnapshotClass \
--hook-kind=checkpoint \
--log-level=debug \
--verbose

cpd-cli oadp backup create ${PROJECT_SCHEDULING_SERVICE}-offline \
--backup-type singleton \
--include-namespaces=${PROJECT_SCHEDULING_SERVICE} \
--include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' \
--prehooks=false \
--posthooks=false \
--with-checkpoint \
--log-level=debug \
--verbose \
--hook-kind=checkpoint \
--selector 'icpdsupport/ignore-on-nd-backup notin (true)'

cpd-cli oadp backup validate \
--backup-type singleton \
--include-namespaces=${PROJECT_SCHEDULING_SERVICE} \
--backup-names ${PROJECT_SCHEDULING_SERVICE}-offline \
--log-level trace \
--verbose \
--hook-kind checkpoint
```
(5.0 백업은 5.1.0 에 복원 불가 / s390x 는 x86_64 워크스테이션에서)

### 2.3 인스턴스(테넌트) 백업
Notes: NFS 는 no_root_squash 필수 / 백업 중 일부 파드 Running 은 정상 /
스냅샷 수 제한은 스토리지 제공자 문서 / 5.0 명령으로도 가능
Important: 5.1.0·5.1.1 → 5.1.2 업그레이드했으면 새 백업 필수
```bash
${OC_LOGIN}
# 5.1.0 만: oc label pvc,pods -l k8s.enterprisedb.io/cluster,velero.io/exclude-from-backup=true velero.io/exclude-from-backup- -n ${PROJECT_CPD_INST_OPERANDS}

# 사설 레지스트리
cpd-cli oadp tenant-backup create ${TENANT_OFFLINE_BACKUP_NAME} \
--namespace ${OADP_PROJECT} \
--vol-mnt-pod-mem-request=1Gi \
--vol-mnt-pod-mem-limit=4Gi \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--mode offline \
--image-prefix=PRIVATE_REGISTRY_LOCATION/ubi9 \
--log-level=debug \
--verbose &> ${TENANT_OFFLINE_BACKUP_NAME}.log&
# (Entitled: --image-prefix=registry.redhat.io/ubi9)
# Note: 볼륨 단계 실패 시 --vol-mnt-pod-mem-limit 증가 (TB 급)

cpd-cli oadp tenant-backup list                                    # Completed
cpd-cli oadp tenant-backup status ${TENANT_BACKUP_NAME} --details  # cpd-tenant-xxx(리소스) · cpd-tenant-vol-yyy(볼륨)
cpd-cli oadp backup status <SUB_BACKUP_NAME> --details
cpd-cli oadp tenant-backup log ${TENANT_BACKUP_NAME}
```
Best practice: 외부 DB 연동 서비스는 외부 DB 도 같은 시점에 백업.

### 2.4 백업 후 — RStudio(5.1.2+) · Data Refinery(5.1.0) · wx.ai(5.1.0) — 모비스 해당 없음

## 4. Restoring to the same cluster

### 4.1 스케줄러 복원 — Note: 먼저 스케줄러 언인스톨
```bash
${OC_LOGIN}
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp restore create ${PROJECT_SCHEDULING_SERVICE}-restore \
--from-backup=${PROJECT_SCHEDULING_SERVICE}-offline \
--include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' \
--include-cluster-resources=true \
--skip-hooks \
--log-level=debug \
--verbose
```

### 4.2 인스턴스 복원
Notes: 다른 프로젝트로 복원 불가 / 유지보수 모드 CR 은 복원 후 손으로 해제 /
Failed·PartiallyFailed → 청소 후 재시작
```bash
${OC_LOGIN}
cpd-cli oadp tenant-restore create ${TENANT_OFFLINE_BACKUP_NAME}-restore \
--from-tenant-backup ${TENANT_OFFLINE_BACKUP_NAME} \
--image-prefix=${PRIVATE_REGISTRY_LOCATION}/ubi9 \
--verbose \
--log-level=debug &> ${TENANT_OFFLINE_BACKUP_NAME}-restore.log&

${CPDM_OC_LOGIN}
cpd-cli manage get-cr-status --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}   # 전부 Completed/Succeeded
cpd-cli oadp tenant-restore list
cpd-cli oadp tenant-restore status ${TENANT_BACKUP_NAME}-restore --details    # cpd-tenant-r-xxx
cpd-cli oadp tenant-restore log ${TENANT_BACKUP_NAME}-restore
```
