```bash
cpd-cli oadp service-registry check \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--verbose \
--log-level debug
```
- 미지원 서비스는 자체 백업 절차 또는 export-import 유틸 검토.
- 전제: cpfs 프로파일 Small 이상 / 전 서비스 동일 릴리스 / 컨트롤플레인 단일 프로젝트 / 오퍼레이터·인스턴스 정상 상태.

## Overview

Restic(파일 복사) 백업을 S3 호환 오브젝트 스토어에 생성. 고수준 5단계:
①백업 준비 → ②오프라인 백업 생성 → ③복원 준비 → ④다른 클러스터로 복원 → ⑤복원 후 작업.

## 1. Preparing to back up (준비 1.1~1.18)

- **1.1 환경변수**: OC_LOGIN·CPDM_OC_LOGIN·PROJECT_CPD_INST_OPERATORS/OPERANDS·PROJECT_SCHEDULING_SERVICE(스케줄러 있을 때만)·TETHERED(_LIST)(테더드 있을 때만)·OADP_PROJECT·TENANT_OFFLINE_BACKUP_NAME
- **1.2 버전 점검** [★채택 — 백업 전 점검에 추가]:
```bash
oc get csv -A | grep "OADP Operator"     # 1.4.x 확인
cpd-cli oadp version                     # cpd-cli oadp 5.1.0 확인
```
- **1.3 (Optional) du-pv 용량 추정** — ★"Note: Do not use this feature in production environments" (C8 근거 원문 재확인). 절차: cpdbr-agent 설치(`--namespace=${OADP_PROJECT} --cpd-namespace=${PROJECT_CPD_INST_OPERANDS}`) → CPDBR_ENABLE_FEATURES=volume-util → du-pv. 모비스 실행 금지.
- **1.4 MongoDB 관련 ConfigMap 제거** — CP4D **4.8.4 이하에서 업그레이드한 이력**이 있으면 오퍼랜드 NS 에서:
```bash
oc delete cm zen-cs-aux-br-cm
oc delete cm zen-cs-aux-ckpt-cm
oc delete cm zen-cs-aux-qu-cm
oc delete cm zen-cs2-aux-ckpt-cm
```
  (★모비스: 5.1.3 설치 이력 실측 — 4.8 계보에서 올라온 게 아니면 해당 없음. cm 존재 여부로 판별 가능)
- **1.5 PostgreSQL(CNPG/EDB) 프라이머리↔복제 동기화 점검** — 어긋나 있으면 트러블슈팅 문서대로 조치 [★백업 전 점검 목록에 이미 반영됨]
- **1.6 (Optional) 외부 PVC 백업 제외** — 수동 생성한 큰 PVC 제외 가능:
  Restic 은 PVC 와 그걸 마운트한 파드 둘 다 `velero.io/exclude-from-backup=true` 라벨 / 내용물만 비우려면 `icpdsupport/empty-on-backup=true`
- **1.7 CCS ConfigMap** — `5.1.0 전용` (download-images 파드 Running 시 cm 수정) → 모비스 5.1.3 해당 없음
- **1.8 Spark(AnalyticsEngine) 정리** — `5.1.0 전용` → 해당 없음
- **1.9 Data Refinery 중지** — `5.1.0 전용` → 해당 없음
- **1.10 ★Db2 준비 (모비스 db2oltp 해당)**:
```bash
# 클러스터 이름 조회
oc get db2ucluster -A -ojsonpath='{.items[?(@.spec.environment.dbType=="db2oltp")].metadata.name}'
export DB2UCLUSTER=<db2ucluster_name>
# 라벨 (백업 훅이 Db2 인식)
oc label db2ucluster ${DB2UCLUSTER} db2u/cpdbr=db2u --overwrite
oc get db2ucluster ${DB2UCLUSTER} --show-labels
# Q Replication 켜져 있으면 중지 (qrep 파드 exec → su - dsadm →)
$BLUDR_HOME/scripts/bin/bludr-stop.sh
# "REPLICATION ENDED SAFELY" 확인 (5.1.0-5.1.1 만 모니터 중지 선행)
```
- **1.11 Db2 Warehouse** — 모비스 미설치 → 해당 없음 (절차는 1.10 과 동일 패턴, dbType=db2wh)
- **1.12 Match 360**(5.1.1) / **1.13 RStudio**(5.1.2+) / **1.14 SPSS** / **1.15 Watson Discovery** / **1.16 watsonx.ai**(5.1.0) / **1.17 wxCA4Z**(5.1.2+) — 전부 모비스 미설치 서비스 → 해당 없음
- **1.18 ★전 서비스 상태 확인**:
```bash
cpd-cli manage get-cr-status --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}   # 전부 Completed 이어야
```

## 2. Creating an offline backup

- **2.1 모드**: 기본 Kubernetes 모드(클러스터 관리자 로그인 필요). REST 모드는 장시간 백업 시 토큰 만료 회피용 — 단 ★스케줄러 백업·모든 복원은 Kubernetes 모드 필수. 모드 리셋: `cpd-cli oadp client config set runtime-mode=`
- **2.2 스케줄러 백업** (설치돼 있을 때만 — 모비스 [사수결정: scheduler]):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp client config set namespace=${OADP_PROJECT}
# 5.1.1+ : precheck → create → validate (모두 --backup-type singleton)
cpd-cli oadp backup precheck --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --exclude-checks ValidVolumeSnapshotClass --hook-kind=checkpoint --log-level=debug --verbose
cpd-cli oadp backup create ${PROJECT_SCHEDULING_SERVICE}-offline --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --prehooks=false --posthooks=false --with-checkpoint --log-level=debug --verbose --hook-kind=checkpoint --selector 'icpdsupport/ignore-on-nd-backup notin (true)'
cpd-cli oadp backup validate --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --backup-names ${PROJECT_SCHEDULING_SERVICE}-offline --log-level trace --verbose --hook-kind checkpoint
```
- **2.3 ★인스턴스(테넌트) 백업 — 본체**:
  Note: ★NFS 는 no_root_squash 필수 / 5.1.0→5.1.2 업그레이드했다면 새 백업 필수 / (5.1.0 만) EDB 복제 PVC 라벨 해제 선행
```bash
# 사설 레지스트리 클러스터
cpd-cli oadp tenant-backup create ${TENANT_OFFLINE_BACKUP_NAME} \
--namespace ${OADP_PROJECT} \
--vol-mnt-pod-mem-request=1Gi \
--vol-mnt-pod-mem-limit=4Gi \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--mode offline \
--image-prefix=PRIVATE_REGISTRY_LOCATION/ubi9 \
--log-level=debug \
--verbose &> ${TENANT_OFFLINE_BACKUP_NAME}.log&
```
  (볼륨 단계 실패 시 --vol-mnt-pod-mem-limit 증가 — TB급 데이터. ★우리 규칙: &백그라운드 대신 tmux)
  확인: `tenant-backup list`(Completed) / `tenant-backup status <이름> --details`(cpd-tenant-xxx=리소스, cpd-tenant-vol-yyy=볼륨) / `tenant-backup log <이름>`
  Best practice: 외부 DB 연동 서비스가 있으면 외부 DB 도 같은 시점에 백업.
- **2.4 백업 후 원복** — RStudio 유지보수 해제(5.1.2+)·Data Refinery 재기동(5.1.0)·watsonx.ai 스케일업(5.1.0) → 모비스 해당 없음

## 3. Preparing to restore to a different cluster  *(다른 클러스터 판 고유 — DR 참고)*

- **3.1 타깃 클러스터 준비**: 소스와 동일한 스토리지클래스·ICSP(이미지 콘텐츠 소스 정책)·글로벌 풀 시크릿·하드웨어 아키텍처·OCP 버전·노드 구성. IBM Cloud↔비IBM Cloud 이동 불가. 노드 지정은 노드 라벨 방식 권장.
  절차: OADP 프로젝트 생성 → node-selector 어노테이션 → ★cpdbr-tenant **--rbac-only** 설치(오퍼레이터 프로젝트는 아직 없어도 되고 ★수동 생성 금지 — 복원이 만든다):
```bash
cpd-cli oadp install \
--component=cpdbr-tenant \
--namespace ${OADP_PROJECT} \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--cpdbr-hooks-image-prefix=${PRIVATE_REGISTRY}/cpdbr-oadp:${VERSION} \
--cpfs-image-prefix=${PRIVATE_REGISTRY} \
--rbac-only \
--log-level=debug \
--verbose
```
  → OADP 오퍼레이터 설치 → cloud-credentials 시크릿(★"특수문자 # 금지" 명시) → ★권장 DPA(아래) → 파드 확인 → ★backup-location Available 확인:
```bash
cpd-cli oadp backup-location list    # PHASE = Available 이어야
```
  → jq 설치 → 유틸 구성 → cert-manager·License Service(소스와 동일 버전) 설치.
- **★공식 권장 DPA 전문** (같은 클러스터 재설치에도 그대로 유효한 표준형):
```yaml
spec:
  configuration:
    velero:
      customPlugins:
      - image: ${CPDBR_VELERO_PLUGIN_IMAGE_LOCATION}
        name: cpdbr-velero-plugin
      defaultPlugins:
      - aws
      - openshift
      - csi          # ※바로 위 Important: Restic 만 쓰면 csi 제거 — 예제보다 Important 우선
      podConfig:
        resourceAllocations:
          limits:
            cpu: "${VELERO_POD_CPU_LIMIT}"
            memory: 4Gi
          requests:
            cpu: 500m
            memory: 256Mi
      resourceTimeout: 60m          # ★공식 yaml 에 실재 (C7-① 원문 근거)
    nodeAgent:
      enable: true
      uploaderType: restic
      timeout: 72h                  # Restic 타임아웃 기본 1h — pod volume timeout 에러 시 증가 (Important)
      podConfig:
        resourceAllocations:
          limits:
            cpu: "${NODE_AGENT_POD_CPU_LIMIT}"   # ★공식 변수명 (런북은 RESTIC_OR_NODE_AGENT_POD_CPU_LIMIT)
            memory: 32Gi
          requests:
            cpu: 500m
            memory: 256Mi
        tolerations:
        - key: icp4data
          operator: Exists
          effect: NoSchedule
  backupImages: false
  backupLocations:
    - velero:
        provider: aws
        default: true
        objectStorage:
          bucket: ${BUCKET_NAME}
          prefix: ${BUCKET_PREFIX}
        config:
          region: ${REGION}
          s3ForcePathStyle: "true"
          s3Url: ${S3_URL}
        credential:
          name: cloud-credentials
          key: cloud
```
  Important(원문): 소스·타깃의 backupLocations.velero.objectStorage 는 동일해야 함. (5.1.0~5.1.2 + Orchestrate 시 appcon-plugin 추가 — 모비스 해당 없음)
- **3.2 이전 복원 흔적 청소**: `cpd-pre-restore-cleanup.sh` (github IBM/cpd-cli **cpdops/5.1.3** — 우리 cpdops-5.1.3.tgz 에 포함):
```bash
./cpd-pre-restore-cleanup.sh --tenant-operator-namespace="${PROJECT_CPD_INST_OPERATORS}"
# 오퍼레이터 프로젝트가 없거나 특정 NS 만 지울 때:
./cpd-pre-restore-cleanup.sh --additional-namespaces="${PROJECT_CPD_INST_OPERATORS},${PROJECT_CPD_INST_OPERANDS}"
```
  스케줄러가 설치돼 있었다면 언인스톨 선행.

## 4. Restoring to a different cluster

- **4.1 스케줄러 복원** (소스에 있었을 때만):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp restore create ${PROJECT_SCHEDULING_SERVICE}-restore \
--from-backup=${PROJECT_SCHEDULING_SERVICE}-offline \
--include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' \
--include-cluster-resources=true \
--skip-hooks \
--log-level=debug \
--verbose
```
- **4.2 ★인스턴스 복원**:
  Notes: 다른 프로젝트명으로 복원 불가 / Failed·PartiallyFailed 나면 청소 후 재시도 / 유지보수 모드로 백업된 CR 은 복원 후 수동 해제
```bash
cpd-cli oadp tenant-restore create ${TENANT_OFFLINE_BACKUP_NAME}-restore \
--from-tenant-backup ${TENANT_OFFLINE_BACKUP_NAME} \
--image-prefix=${PRIVATE_REGISTRY_LOCATION}/ubi9 \
--verbose \
--log-level=debug &> ${TENANT_OFFLINE_BACKUP_NAME}-restore.log&
```
  확인: get-cr-status 전부 Completed/Succeeded / `tenant-restore list` / `tenant-restore status <이름>-restore --details`(cpd-tenant-r-xxx) / `tenant-restore log`
