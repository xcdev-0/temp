## Overview

Restic = 파일시스템 복사 방식(OADP 기반) — **S3 호환 오브젝트 스토어로만** 백업 저장.
5단계: ①백업 준비 ②오프라인 백업 생성 ③복원 전 청소 ④복원 ⑤복원후 작업

## 1. Preparing to back up

- **1.1 환경변수**: OC_LOGIN·CPDM_OC_LOGIN·OPERATORS·OPERANDS·SCHEDULING(스케줄러 시)·TETHERED(_LIST)·OADP_PROJECT·**TENANT_OFFLINE_BACKUP_NAME**
- **1.2 버전 확인**: OADP 오퍼레이터 1.4.x (`oc get csv -A | grep "OADP Operator"`) / `cpd-cli oadp version` → 5.1.0
- **1.3 (선택) 용량 추정** — Note: **운영 환경 사용 금지**. cpdbr-agent(특권 모드 노드 에이전트) 설치 후:
```bash
cpd-cli oadp install --component=cpdbr-agent --namespace=${OADP_PROJECT} --cpd-namespace=${PROJECT_CPD_INST_OPERANDS}
export CPDBR_ENABLE_FEATURES=volume-util
cpd-cli oadp du-pv
```
- **1.4 MongoDB ConfigMap 잔재 제거** (CP4D 4.8.4 이하에서 업그레이드한 이력 시): `oc delete cm zen-cs-aux-br-cm zen-cs-aux-ckpt-cm zen-cs-aux-qu-cm zen-cs2-aux-ckpt-cm`
- **1.5 PostgreSQL 복제 동기화 점검** (CNPG·EDB — 트러블슈팅 문서)
- **1.6 외부 볼륨 제외** (선택): Restic 백업에서 PVC+내용 제외 = PVC 에 `velero.io/exclude-from-backup=true` 라벨 + 그 PVC 마운트하는 파드에도 같은 라벨(oc describe pvc 의 Mounted By 로 찾기) / PVC 정의만 남기고 내용 비우기 = `icpdsupport/empty-on-backup=true`. 복원 때 제외 PVC 수동 재생성 필요할 수 있음
- 1.7 CCS ConfigMap(cpd-ccs-maint-br-cm) — **5.1.0 만** → 건너뜀
- 1.8 Spark 런타임 정리 — 5.1.0 만 → 건너뜀 / 1.9 Data Refinery 정지 — 5.1.0 만 → 건너뜀
- **1.10 Preparing Db2 ★모비스 필수**:
```bash
oc get db2ucluster -A -ojsonpath='{.items[?(@.spec.environment.dbType=="db2oltp")].metadata.name}'
export DB2UCLUSTER=<db2ucluster_name>
oc label db2ucluster ${DB2UCLUSTER} db2u/cpdbr=db2u --overwrite
oc get db2ucluster ${DB2UCLUSTER} --show-labels
```
  Q Replication 사용 시: qrep 파드 exec → `su - dsadm` → (5.1.0~5.1.1 모니터 중지) → `$BLUDR_HOME/scripts/bin/bludr-stop.sh` → "REPLICATION ENDED SAFELY ... SERVER STATUS: INACTIVE" 확인
- 1.11 Db2 Warehouse — 미설치 → 건너뜀 / 1.12 Match360(5.1.1) — 미설치 / 1.13 RStudio(5.1.2+) — 미설치 / 1.14 SPSS — 미설치 / 1.15 Discovery — 미설치 / 1.16 wx.ai 스케일다운 — 5.1.0 만+미설치 / 1.17 wxCA for Z — 미설치
- **1.18 전 서비스 Completed 확인**: `cpd-cli manage get-cr-status --cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}`

## 2. Creating an offline backup

- **2.1 모드**: 기본 Kubernetes 모드. ★스케줄러 백업·모든 복원 = Kubernetes 모드 필수(클러스터 관리자). REST 모드는 긴 백업의 토큰 만료 회피용(백업·체크포인트만) — 모비스 불사용
- **2.2 스케줄러 백업** (설치 시 — 5.1.1+):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp client config set namespace=${OADP_PROJECT}
cpd-cli oadp backup precheck --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --exclude-checks ValidVolumeSnapshotClass --hook-kind=checkpoint --log-level=debug --verbose
cpd-cli oadp backup create ${PROJECT_SCHEDULING_SERVICE}-offline --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --prehooks=false --posthooks=false --with-checkpoint --log-level=debug --verbose --hook-kind=checkpoint --selector 'icpdsupport/ignore-on-nd-backup notin (true)'
cpd-cli oadp backup validate --backup-type singleton --include-namespaces=${PROJECT_SCHEDULING_SERVICE} --backup-names ${PROJECT_SCHEDULING_SERVICE}-offline --log-level trace --verbose --hook-kind checkpoint
```
  (5.1.0 은 --backup-type singleton 없이. 5.0 백업은 5.1 복원 불가. s390x 는 x86 워크스테이션에서)
- **2.3 테넌트 백업 ★핵심 — 런북에 없던 실제 명령**:
  - Note: ★**NFS 는 no_root_squash 필수** / 백업 중 일부 파드 Running 은 정상(수동 종료 불필요)
  - Important [9/2 대조로 추가]: 5.1.0/5.1.1→5.1.2 업그레이드 이력이 있으면 **새 백업 필수** (모비스 설치 계보 실측 — 5.1.3 직설치면 무관)
  - (5.1.0 EDB 복제 PVC 라벨 복구 — 5.1.3 은 해당 시만)
  - 사설 레지스트리 클러스터:
```bash
cpd-cli oadp tenant-backup create ${TENANT_OFFLINE_BACKUP_NAME} \
--namespace ${OADP_PROJECT} \
--vol-mnt-pod-mem-request=1Gi \
--vol-mnt-pod-mem-limit=4Gi \
--tenant-operator-namespace ${PROJECT_CPD_INST_OPERATORS} \
--mode offline \
--image-prefix=PRIVATE_REGISTRY_LOCATION/ubi9 \
--log-level=debug \
--verbose &> ${TENANT_OFFLINE_BACKUP_NAME}.log&
```
  - (Entitled Registry 클러스터는 --image-prefix=registry.redhat.io/ubi9)
  - Note: 볼륨 백업 단계 실패 시 --vol-mnt-pod-mem-limit 증가 (TB급 데이터)
  - 확인:
```bash
cpd-cli oadp tenant-backup list                                   # Completed
cpd-cli oadp tenant-backup status ${TENANT_BACKUP_NAME} --details  # cpd-tenant-xxx(리소스)·cpd-tenant-vol-yyy(볼륨)
cpd-cli oadp tenant-backup log ${TENANT_BACKUP_NAME}
```
  - Best practice: 외부 DB 연동 서비스는 외부 DB 도 같은 시점 백업
- **2.4 백업 후 작업**: RStudio(5.1.2+ 유지보수 해제)·Data Refinery(5.1.0 재기동)·wx.ai(5.1.0 스케일업) — 모비스 전부 해당 없음

## 4. Restoring to the same cluster

- **4.1 스케줄러 복원** — ★선행: 언인스톨 (Uninstalling the scheduling service — 삼성 수집분 `원문-언인스톨-플랫폼-스케줄러.md` 5.4 판, 5.1.x 판 대조 필요):
```bash
cpd-cli oadp client config set cpd-namespace=${PROJECT_SCHEDULING_SERVICE}
cpd-cli oadp restore create ${PROJECT_SCHEDULING_SERVICE}-restore --from-backup=${PROJECT_SCHEDULING_SERVICE}-offline --include-resources='operatorgroups,configmaps,catalogsources.operators.coreos.com,subscriptions.operators.coreos.com,customresourcedefinitions.apiextensions.k8s.io,scheduling.scheduler.spectrumcomputing.ibm.com' --include-cluster-resources=true --skip-hooks --log-level=debug --verbose
```
- **4.2 인스턴스 복원 ★C4-a 의 답** — ⛔다른 NS 불가 / Failed·PartiallyFailed → §3 부터 재시작 / 유지보수 모드 CR 은 복원 후 수동 해제:
```bash
cpd-cli oadp tenant-restore create ${TENANT_OFFLINE_BACKUP_NAME}-restore \
--from-tenant-backup ${TENANT_OFFLINE_BACKUP_NAME} \
--image-prefix=${PRIVATE_REGISTRY_LOCATION}/ubi9 \
--verbose \
--log-level=debug &> ${TENANT_OFFLINE_BACKUP_NAME}-restore.log&
```
  - 확인: `get-cr-status`(전부 Completed/Succeeded) / `tenant-restore list` / `tenant-restore status <이름> --details`(cpd-tenant-r-xxx 하위) / `tenant-restore log <이름>`
