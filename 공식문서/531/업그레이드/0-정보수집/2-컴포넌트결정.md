## Upgrade phase (문서의 위치 표시)

Collecting required information ← 여기 → client workstation → restricted
network → private registry → prerequisite software → shared cluster
components → preparing instance → upgrading instance

## Before you begin (요지)

- 환경변수 스크립트 세팅 후 source 하면 명령 그대로 실행 가능 (Best practice)
- 다중 인스턴스: 인스턴스별 독립 업그레이드 가능, 버전 섞여도 됨
  (예: 하나는 5.1.2, 하나는 5.3.1)
- Version support (Important): 한 인스턴스 안의 전 컴포넌트는 동일 버전 필수
- 업그레이드 옵션: 개별(세밀 제어, 단계 많음·순서 중요 — ★오퍼레이터는
  어차피 동시 업그레이드) vs 일괄(단계 적음, cpd-cli 가 순서 보장)

## Procedure (전문)

```bash
# 1. 로그인
${CPDM_OC_LOGIN}

# 2. 스케줄러 설치 여부
oc get scheduling -A
#   결과 있음 → ★COMPONENTS 에 scheduler 포함할 것 (프로젝트·버전 표시됨)
#   빈 응답  → 미설치

# 3. 인스턴스에 설치된 서비스 목록
cpd-cli manage list-deployed-components \
--cpd_instance_ns=${PROJECT_CPD_INST_OPERANDS}
#   ★Important: ws 가 나오면 COMPONENTS 에 ws_runtimes 추가할 것
```
