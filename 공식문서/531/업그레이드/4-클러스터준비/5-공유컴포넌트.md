# 원문 — Upgrading shared cluster components (5.1→5.3) `[2026-09-02 수집]`

경로: 5.3.x → Upgrading from Version 5.1 → Preparing your cluster → **Upgrading shared cluster components**
URL: https://www.ibm.com/docs/en/software-hub/5.3.x?topic=cluster-upgrading-shared-components [확정]
문서 갱신일: 2026-08-20

> ★우리 판정:
> ```
> ① License Service 업그레이드(apply-cluster-components)는 런북 p.48~49 와 동일 [대조 일치]
>    + 추가 수확: "[SUCCESS] The apply-cluster-components command ran successfully"
>    메시지를 기다렸다가 다음으로 (런북에 없던 대기 조건)
> ② ★스케줄러 업그레이드 명령 확보 — 런북에 없음! (런북은 설치 확인만 하고 업그레이드 안 함):
>    apply-scheduler --release --patch_id --license_acceptance --scheduler_ns
>    --image_pull_prefix --image_pull_secret
>    → 스케줄러 조건부 누락 3종 세트 완성: ④-b 전역리소스 + ④-c NS 풀시크릿 + ④-d apply-scheduler
>    모비스 스케줄러 실측 = 이 3종의 실행 여부를 한 번에 결정
> ③ 다중 인스턴스면 공유 컴포넌트는 최신 목표 버전으로 (모비스 단일 — 무관)
> ④ cert-manager 감지 언급은 이 페이지에 없음 — 그 설명은 런북 서두(p.6)와
>    Migrating to RH cert-manager 문서 쪽 [기존 이해 유지]
> ```

## 본문 요지 + 명령

사전 확인 (런북과 동일):
```bash
oc get deployment -A |  grep ibm-licensing-operator   # License NS 확인
oc get scheduling -A                                  # 스케줄러 설치 확인
```

1. ${CPDM_OC_LOGIN}
2. License Service 업그레이드:
```bash
cpd-cli manage apply-cluster-components \
--release=${VERSION} \
--patch_id=${PATCH_ID} \
--license_acceptance=true \
--licensing_ns=${PROJECT_LICENSE_SERVICE}
```
   (PROJECT_CS_CONTROL 변형 동일 구조)
   ★"[SUCCESS] ... ran successfully" 나올 때까지 대기 후 진행
3. License 파드 Running/Completed 확인
4. ★스케줄러 설치 시 — 업그레이드 (런북 누락분):
```bash
cpd-cli manage apply-scheduler \
--release=${VERSION} \
--patch_id=${PATCH_ID} \
--license_acceptance=true \
--scheduler_ns=${PROJECT_SCHEDULING_SERVICE} \
--image_pull_prefix=${IMAGE_PULL_PREFIX} \
--image_pull_secret=${IMAGE_PULL_SECRET}
```
5. 스케줄러 파드 Running/Completed 확인
