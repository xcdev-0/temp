# 원문 — Checking the health of your cluster (5.1→5.3) `[2026-09-02 수집]`

경로: 5.3.x → Upgrading from Version 5.1 → Preparing to upgrade an instance → **Checking the health of your cluster**
URL: [미확인 — 주소 받으면 기입]
문서 갱신일: 2026-08-20

> ★우리 판정:
> ```
> ① ★런북(p.50)은 3종인데 공식은 4종 — 네 번째 검사 확보:
>    cpd-cli health network-connectivity --control_plane_ns=${PROJECT_CPD_INST_OPERANDS}
>    (오퍼레이터↔오퍼랜드 파드 연결까지 검사) → 실행판 점검에 추가 가치
> ② ★폐쇄망 함정 주석 확보: cluster 검사의 "Image Registry Connectivity Test" 는
>    icr.io·github·mirror.openshift.com 도달 검사라 폐쇄망에선 FAIL 이 정상 —
>    "If you pull images from a private container registry, [FAIL] is an acceptable
>    result" [원문]. 현장에서 FAIL 보고 당황하지 않기
> ③ 합격 기준 숫자 확보: 노드 자원 사용 90% 미만 / 네트워크 처리량 최소 350 MB/s
> ④ 성격: 선택이지만 강력 권장(strongly recommended)
> ```

## 본문 요지 + 명령

```bash
${CPDM_OC_LOGIN}

# ① 클러스터 (버전·MCP·CO·etcd — ★폐쇄망은 레지스트리 도달검사 FAIL 정상)
cpd-cli health cluster

# ② 노드 (READY + 자원 90% 미만)
cpd-cli health nodes

# ③ 네트워크 처리량 (최소 350 MB/s — 사설 레지스트리 변형 있음)
cpd-cli health network-performance \
--image-prefix=${PRIVATE_REGISTRY_LOCATION}

# ④ ★네트워크 연결 (런북에 없는 검사 — 오퍼레이터↔오퍼랜드 연결 포함)
cpd-cli health network-connectivity \
--control_plane_ns=${PROJECT_CPD_INST_OPERANDS}
```

기대 결과 표 요지: Cluster Version·MCP·Cluster Operator·etcd = SUCCESS /
CSR = SKIP 가능 / 폐쇄망 레지스트리 도달 = FAIL 허용 /
노드 READY·자원<90% / throughput ≥350MB/s / 연결 4종 SUCCESS
