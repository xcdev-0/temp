# CPD 5.3.1 백업 이미지 미러링

확인일: 2026-09-10. 1~4절은 [현장 DPA](dpa)의 사용자 플러그인 4개를 같은 경로로 반입한다. 5절은 누락된 tenant 서비스 이미지 `cpdbr-oadp:5.3.1.12`를 삼성 배스천의 기존 Skopeo 방식으로 추가 반입한다.  
근거: [IBM 5.3.x OADP 설치·구성](https://www.ibm.com/docs/en/software-hub/5.3.x?topic=software-installing-configuring-oadp-utility) 중 폐쇄망 이미지 반입 절차. 아래 명령은 문서로 작성했으며 실제 다운로드·푸시는 수행하지 않았다.

## 1. 연결망에서 다운로드

실행 위치: 인터넷 연결 작업 호스트. `cpd-cli 14.3.1`과 해당 5.3.1 관리 컨테이너가 준비된 상태에서 실행한다. `cpd-cli version`으로 실제 바이너리 버전을 확인한다.

기존 현대 반입 작업의 워크스페이스를 사용한다. 설치 경로가 다르면 환경변수를 실제 위치로 수정한다.

```bash
export CPD_CLI_MANAGE_WORKSPACE=/ibm/mobis2/export/cpd/5.3.1-patch12
mkdir -p "${CPD_CLI_MANAGE_WORKSPACE}/work/offline"

cpd-cli manage save-image \
  --from=icr.io/cpopen/cpfs/cpfs-oadp-plugins:latest

cpd-cli manage save-image \
  --from=icr.io/cpopen/cpd/cpdbr-velero-plugin:5.3.1

cpd-cli manage save-image \
  --from=icr.io/cpopen/cpd/swhub-velero-plugin:5.3.1

cpd-cli manage save-image \
  --from=icr.io/db2u/db2u-velero-plugin:5.3.1
```

**확인:** 네 명령이 각각 성공하고 `work/offline`에 압축 이미지 파일이 생성되어야 한다. 플랫폼 미러링으로 이미 사설 저장소에 준비된 이미지는 중복 반입할 필요가 없다.

## 2. 폐쇄망으로 파일 반입

연결망의 다음 파일 4개를 폐쇄망 배스천의 `${CPD_CLI_MANAGE_WORKSPACE}/work/offline`에 넣는다. 명령 출력의 실제 파일명도 확인한다.

```text
icr.io_cpopen_cpfs_cpfs-oadp-plugins_latest.tar.gz
icr.io_cpopen_cpd_cpdbr-velero-plugin_5.3.1.tar.gz
icr.io_cpopen_cpd_swhub-velero-plugin_5.3.1.tar.gz
icr.io_db2u_db2u-velero-plugin_5.3.1.tar.gz
```

파일을 생성한 연결망 호스트의 설정과 폐쇄망 호스트의 설정은 별개다. 폐쇄망에서도 아래 환경변수를 지정해야 해당 위치의 파일을 사용한다.

## 3. 사설 레지스트리로 복사

실행 위치: 폐쇄망 배스천. 사설 레지스트리 **쓰기 권한**으로 로그인한다. `PRIVATE_REGISTRY_LOCATION`은 DPA에 사용할 같은 `host:port` 값이며 `https://`를 붙이지 않는다.

```bash
export CPD_CLI_MANAGE_WORKSPACE=/ibm/mobis2/export/cpd/5.3.1-patch12
read -rp 'Private registry (host:port): ' PRIVATE_REGISTRY_LOCATION
export PRIVATE_REGISTRY_LOCATION
read -rp 'Registry user: ' PRIVATE_REGISTRY_PUSH_USER
read -rsp 'Registry password: ' PRIVATE_REGISTRY_PUSH_PASSWORD
printf '\n'

cpd-cli manage login-private-registry \
  "${PRIVATE_REGISTRY_LOCATION}" \
  "${PRIVATE_REGISTRY_PUSH_USER}" \
  "${PRIVATE_REGISTRY_PUSH_PASSWORD}"
unset PRIVATE_REGISTRY_PUSH_PASSWORD
```

로그인 성공 후 아래 네 명령을 실행한다.

```bash
cpd-cli manage copy-image \
  --from=icr.io/cpopen/cpfs/cpfs-oadp-plugins:latest \
  --to="${PRIVATE_REGISTRY_LOCATION}/cpopen/cpfs/cpfs-oadp-plugins:latest"

cpd-cli manage copy-image \
  --from=icr.io/cpopen/cpd/cpdbr-velero-plugin:5.3.1 \
  --to="${PRIVATE_REGISTRY_LOCATION}/cpopen/cpd/cpdbr-velero-plugin:5.3.1"

cpd-cli manage copy-image \
  --from=icr.io/cpopen/cpd/swhub-velero-plugin:5.3.1 \
  --to="${PRIVATE_REGISTRY_LOCATION}/cpopen/cpd/swhub-velero-plugin:5.3.1"

cpd-cli manage copy-image \
  --from=icr.io/db2u/db2u-velero-plugin:5.3.1 \
  --to="${PRIVATE_REGISTRY_LOCATION}/db2u/db2u-velero-plugin:5.3.1"
```

## 4. 결과 확인

- 네 복사 명령이 모두 성공했는지 확인한다.
- 사설 레지스트리에 생성된 주소가 [DPA](dpa)의 4개 `image:` 값과 일치해야 한다.
- `cpfs-oadp-plugins:latest`는 반입한 이미지의 digest도 기록한다.
- DPA 적용 후 Velero의 플러그인 초기화 컨테이너에서 이미지 pull과 초기화가 성공해야 한다. 배스천의 레지스트리 로그인과 클러스터의 pull secret·CA 설정은 별개다.
- 위 1~4절은 사용자 플러그인 4개를 다룬다. 전체 백업에는 OADP, 훅, CPFS 유틸리티, ubi-minimal 등의 이미지도 기존 설치 절차에 따라 준비되어 있어야 한다. 현재 누락이 확인된 tenant 이미지의 추가 반입은 5절을 따른다.

## 5. cpdbr-oadp 추가 다운로드·푸시

### 5.1 기존 목록 확인

기존 DPA 4종은 `cpfs-oadp-plugins:latest`, `cpdbr-velero-plugin:5.3.1`, `swhub-velero-plugin:5.3.1`, `db2u-velero-plugin:5.3.1`이었다. 이 목록에는 `cpdbr-oadp`가 없다. [기존 이미지 push 스크립트](../../../ibm/mobis2/export/scripts/0-setting/3-oadp-images-push.sh)의 PODMAN_LIST와 CPD_LIST에도 `cpdbr-oadp`가 없음을 확인했다.

[삼성 백업 작업 기록](../../../../삼성/실습/13-백업/13-2-백업구성-OADP-BR.md)의 5.4 환경에는 `cpdbr-oadp` 보유 기록이 있지만, 현재 필요한 5.3.1.12 태그의 반입 완료 근거는 아니다. 사용자 조회에서는 사설 레지스트리의 루트 및 `cpopen/cpd` 경로에 해당 태그가 없었다.

추가 대상은 DPA 플러그인이 아니라 **tenant 백업 서비스 이미지**다. 다음은 삼성 기록의 `skopeo copy → rsync → skopeo copy` 방식을 이 이미지에 적용한 명령이며, 이번에 실제 실행한 결과는 아니다.

### 5.2 인터넷 연결 배스천에서 다운로드

실행 위치: `icr.io`에 접근할 수 있는 Linux 배스천. 기존 삼성 반입 디렉터리 `/ibm/samsunglife/export/tools`를 사용한다. Skopeo가 설치되어 있어야 한다. 각 명령이 성공한 뒤 다음 단계로 진행한다.

```bash
mkdir -p /ibm/samsunglife/export/tools

skopeo copy --all --preserve-digests \
  docker://icr.io/cpopen/cpd/cpdbr-oadp:5.3.1.12 \
  dir:/ibm/samsunglife/export/tools/cpdbr-oadp-5.3.1.12
```

여기서는 압축 TAR가 아니라 Skopeo의 `dir:` 형식으로 저장한다. 디렉터리 전체를 옮겨야 한다. `5.3.1.12`는 현재 사용자 CLI가 요청한 태그이며, IBM 원본 레지스트리에서의 다운로드 성공은 이 명령으로 확인한다. 원본에서도 `manifest unknown`이 나오면 기본 5.3.1 이미지를 재태깅하지 말고 실제 CLI 버전과 제공 이미지를 확인한다.

### 5.3 폐쇄망 배스천으로 반입

실행 위치: 다운로드한 인터넷 연결 배스천. 아래 목적지 IP와 경로는 삼성 작업 기록에서 사용한 값이다.

```bash
rsync -av \
  /ibm/samsunglife/export/tools/cpdbr-oadp-5.3.1.12 \
  root@192.168.10.241:/ibm/samsunglife/export/tools/
```

### 5.4 폐쇄망 삼성 배스천에서 로그인·푸시

레지스트리 쓰기 권한이 있는 계정으로 로그인한다. 사용자 이름과 비밀번호는 프롬프트에서 입력한다. 사설 레지스트리의 TLS 검증 옵션은 기존 삼성 작업 명령에 있던 설정을 유지했다.

```bash
skopeo login --tls-verify=false registry.xai-data.spelix.co.kr:5000

skopeo copy --all --preserve-digests \
  --dest-tls-verify=false \
  dir:/ibm/samsunglife/export/tools/cpdbr-oadp-5.3.1.12 \
  docker://registry.xai-data.spelix.co.kr:5000/cpdbr-oadp:5.3.1.12

oc image info registry.xai-data.spelix.co.kr:5000/cpdbr-oadp:5.3.1.12
```

`--all`로 이미지 목록과 하위 아키텍처 이미지를 복사하고, `--preserve-digests`로 digest 보존을 요구한다. 푸시 성공 후 `oc image info`에서 이미지 정보가 정상 출력되어야 한다.

이번 목적지는 `registry.xai-data.spelix.co.kr:5000/cpdbr-oadp:5.3.1.12`로 명시했다. 따라서 이후 tenant 재설치의 hooks 옵션은 다음 값이다.

```text
--cpdbr-hooks-image-prefix=registry.xai-data.spelix.co.kr:5000
```
